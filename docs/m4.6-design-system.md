# Design System (v3 "Aurora", evolved from M4.6)

Vanilla ES modules + CSS custom properties. No framework, no build step, no
runtime dependencies. Layout: `public/index.html` shell → `public/app.js`
router → feature modules in `public/js/` → shared primitives in
`public/js/components.js` and `public/js/charts.js`.

## v3 at a glance

- **Color:** oklch primitives — perceptually uniform lightness, so ok / warn /
  bad at equal L read equally loud. Cyan is the default accent (blue, violet,
  teal remain). Unversioned prefs migrate the old implicit blue once.
- **Surfaces:** translucent "glass" (`.glass`, `.panel`, `.card`,
  `.stat-card`, `.hud-card`) over a fixed atmospheric backdrop (`.atmosphere`:
  drifting aurora + dotted grid). Tables, code, and forms stay on opaque
  sunken surfaces for legibility.
- **Platform features:** View Transitions between routes (`main-view`,
  `nav-indicator`), CSS anchor positioning (attention popover),
  `@starting-style` entries, native `<dialog>` command palette, container
  queries (HUD / analytics reflow by their own width), `color-mix()`.
  Everything degrades to a static-but-correct layout.
- **Stylesheets:** `theme.css` (tokens) → `styles.css` (shared components) →
  `shell.css` (atmosphere, sidebar, top bar, palette, popovers, transitions)
  → `hud.css` (Mission Control, charts, analytics, runbooks) → `views.css`
  (security, approvals, plan/operation, devices) → `infra.css` (scope switch,
  organization pages, visual infrastructure, inspector content).
- **Honesty rules carried forward:** status is always color + text; "as of
  last sync" sits beside every live-looking number; server roles come only
  from collected infrastructure evidence; every chart has its numbers as text.

## Token architecture (three levels)

`public/theme.css` is the only place colors/spacing are defined.

| Level | Prefix / names | Who references it |
|---|---|---|
| Primitive | `--p-*` (ink, paper, cyan, blue, violet, teal, magenta, status hues) | `theme.css` only (plus accent swatches in the appearance menu) |
| Semantic | `--canvas*`, `--surface*`, `--text*`, `--border*`, `--accent*` (incl. `--accent-glow`), `--ok/--warn/--bad/--info/--obs` + `-soft` / `-glow`, `--chart-1..6`, `--chart-grid`, `--aurora-*`, `--grid-dot`, `--focus-ring`, `--overlay`, `--selected-row` | `styles.css` + components |
| Component | `--sidebar-width`, `--sidebar-collapsed`, `--topbar-height`, `--control-height`, `--control-pad-x`, `--table-row-height`, `--panel-width`, `--content-max`, `--badge-fs`, `--radius-*`, `--elev-*`, `--glass-*`, `--motion-*`, `--ease-*`, `--sp-*`, `--fs-*` | component CSS |

## Themes

Applied via attributes on `<html>` (set before first paint by the inline
script in `index.html`; persisted under the `n1_appearance` localStorage key):

- `data-theme="dark"` (default) | `"light"` | `"system"` (attr absent →
  `prefers-color-scheme` media query drives light/dark, follows OS live)
- `data-accent` absent = cyan (default) | `"blue"` | `"violet"` | `"teal"`
- `data-sidebar="collapsed"` (attr absent = expanded)
- `data-density="compact"` (default, attr absent) | `"comfortable"`

All three are independent — light+violet+comfortable works without any
component edits. To add a theme/accent: add one `[data-theme=…]` or
`[data-accent=…]` block in `theme.css` that redefines semantic tokens.
To restyle cards globally: change `--radius-card`/`--elev-1`/`--surface`
once — every card-type surface follows.

`public/theme.js` exports `getAppearance / applyAppearance /
setAppearance / appearanceMenu / wireAppearanceMenu`. `initTheme()`
is inlined in `index.html` `<head>` to avoid a theme flash.

## Status language (honest-state rules)

Collection status comes from `resBadge(r)` — **never** infer health from
retrieval success:

`not collected · collecting… · available · failed · forbidden ·
unsupported · skipped · referenced`

Modifiers render *alongside* the status badge, not instead of it:

- `staleBadge(r)` — fetched > 24h ago
- `completenessBadge(r)` — partial/limited payload
- `historicalBanner(snap)` — viewing a non-latest sealed snapshot
- `state === 'reused'` → `referenced` (linked from an earlier observation)

## Component map (`public/js/components.js`)

| Function | Used for |
|---|---|
| `resBadge(r, {collecting})` | collection-state badge |
| `staleBadge / completenessBadge / historicalBanner` | state modifiers |
| `glanceHtml(byType)` | 4-cell at-a-glance strip (OS/IP/user/policy) |
| `previewLine(type, r)` | one-line resource summary |
| `kvOf(obj)` | key/value sheet |
| `patchBuckets(r)` | pending-patch status buckets |
| `comparisonHtml(comparison, {compact})` | grouped changed/unchanged/n-c rows w/ schema-delta + routine-tick handling |
| `RESOURCE_LABELS`, `STANDARD_RESOURCES` | resource vocabulary |

Feature modules: `js/device-drawer.js` (nonmodal inspector + org drawer +
PowerShell flow), `js/device-page.js` (tabbed details), `js/gallery.js`
(fixture gallery), `js/core.js` (api/state/utils/SSE reader), `app.js`
(shell, remaining views, hash router).

## Adding a resource view without duplicating state plumbing

1. Add the type to `RESOURCE_LABELS` (+ `STANDARD_RESOURCES` if it belongs
   in the standard profile card grid).
2. Write a `typeHtml(r)` renderer for the details tab — return honest
   empty states; only use fields on the adapter allowlist
   (`docs/adapter-capabilities.md`).
3. Mount it via `resSection(byType, type, title, typeHtml)` in the
   appropriate tab in `js/device-page.js` — that wrapper supplies the
   status badge, completeness, staleness, fetch times, and the
   Fetch/Refresh control for free.
4. Add a `previewLine` case if the drawer card should summarize it.
5. Add a fixture to `js/gallery.js` covering its difficult states.

Do **not** hand-roll badge/timestamp markup in the feature — that's the
bug the shared primitives exist to prevent.

## Fixture gallery

Route: `#/gallery` (no nav entry — deep link only). Renders every shared
component against synthetic fixtures: all badge states, stale/reused,
forbidden, partial, failed, empty, long names, null fields, comparison
rows, banners, tabs. Zero tenant calls — safe to open on any server.
Toggle theme/accent/density via sidebar → Appearance to verify both themes.

## Navigation contract (M5 stable surface)

| Hash | Meaning |
|---|---|
| `#/overview` `#/devices` `#/organizations` `#/changes` `#/activity` | top-level views |
| `#/devices?q=&page=&orgId=&offline=&sort=&dir=` | filtered device list |
| `#/investigations` · `#/investigations/<id>` | list / detail |
| `#/device/<id>/<tab>?snap=<snapshotId>` | device page, tab ∈ `overview software patches netstorage alerts history` |
| `#/gallery` | component gallery |

Parameter-only changes (snapshot selection, filters) `replaceState`;
structural changes (view/device/tab/investigation) push history, so
browser back/forward works. An assistant can deep-link any of these —
`#/device/123/software?snap=abc123` opens that exact sealed snapshot.

## Accessibility notes

- Focus ring: `--focus-ring` on `:focus-visible`, all interactive elements.
- Inspector: `role="dialog"`, `aria-modal` toggles with viewport (modal
  <1100px where backdrop renders, nonmodal above), Escape closes, focus
  returns to the opener row.
- Toasts are `role="status"` (polite live region).
- `prefers-reduced-motion` collapses transitions to ~0ms.
- Tabs are buttons with `role="tab"`/`aria-selected`; sortable headers are
  keyboard-operable (`Enter` toggles).
- Status is always color+text, never color alone.
